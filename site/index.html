核心特性

该有的都有，不该有的不打扰

从曲线编辑到实时监控，从托盘集成到硬件安全兜底，全部围绕一个目标：让风扇安静、稳定、可预期。

双轨曲线编辑

画布拖拽控制点，或在表格中精确键入温度/转速，两种方式实时同步。

实时温度与转速

CPU/GPU 温度、目标温度、风扇输出与实际 RPM 一屏掌握，历史窗口 1–480 分钟可调。

四种温度策略

加权、取最大值、仅 CPU、仅 GPU。不同负载场景下，选择更符合你机型的合并方式。

场景预设

内置静音 / 平衡 / 性能三挡，支持新建、保存、恢复与删除自定义挡位。

手动锁定转速

需要绝对安静或满速散热时，一键锁定 0–100% 固定转速，随时切回自动曲线。

托盘与开机自启

动态托盘图标、开机自启与启动提权；Program Files 安装免 UAC，自定义目录登录时请求一次 UAC。

硬件安全兜底

首个有效温度前不接管 EC；连续无温度时释放控制权交还固件；写入失败托盘告警。

本地优先

控制台只监听 127.0.0.1，写接口校验会话令牌与 Host；没有账号，没有云端，没有遥测。

工作原理

一个每秒运转的闭环

读温度 → 合并温度 → 曲线插值 → 写 EC。程序不直接读硬件传感器，而是通过常驻 PowerShell 进程桥接 LibreHardwareMonitor。

01

采集温度

常驻 PowerShell 进程加载 LHM，读取 CPU/GPU 全部温度传感器；子进程异常时指数退避重启。

PowerShell + LHM
02

合并目标温度

按当前策略把两路温度合并成一个目标温度，避免单路传感器噪声直接驱动风扇。

weighted / max / cpu / gpu
03

曲线插值

在 5 点曲线上线性插值出目标转速；2°C 滞回与 30 秒心跳避免频繁写 EC。

InterpolateCurve
04

写入 EC

通过 ec-probe 写风扇寄存器 0x2C/0x2D，并读取 0xB0–0xB3 获取实际 RPM。

ec-probe.exe

安全兜底：宁可交还固件，也不赌旧数据

自动模式在拿到首个有效温度前不接管 EC。连续 3 个周期没有任何有效温度时，程序写入 0xFF 释放风扇控制权并触发托盘告警；温度恢复后自动重新接管。写失败不会记为“已提交”，下一周期会继续重试。

默认每 1 秒采样，6 次采样为一个决策周期；一次写入同时作用于 Fan1/Fan2。

!

写 EC 有风险，请先确认你的机型

EC 寄存器地址因笔记本型号而异。本项目在目标机型上验证了风扇寄存器 0x2C / 0x2D 与 RPM 寄存器 0xB0–0xB3；其他机型可能无效，甚至误触其他 EC 功能。

未知机型请先用 --dry-run 或 --simulate 验证，并用管理员 PowerShell 执行 ec-probe read 0x2C 回读确认。完整探测方法见 README 的硬件兼容性章节。

常见问题

动手之前，先看这几条

会把温度数据上传到云端吗？

不会。所有温度、转速和配置只在你的电脑上处理。配置文件与日志位于 %LOCALAPPDATA%\FanController。

为什么需要管理员权限？

访问 EC 寄存器需要加载 WinRing0 驱动，由 ec-probe.exe 完成读写；没有管理员权限就无法操作硬件。

自定义目录安装后，开机自启会弹 UAC 吗？

会。安装在 Program Files 内时使用最高权限计划任务，登录免 UAC；其他目录使用普通权限计划任务，登录时由程序请求一次 UAC。这样既支持自定义目录，也避免最高权限任务指向用户可写路径。

换一台笔记本能用吗？

不一定。风扇与 RPM 寄存器地址因机型而异，本项目只在目标机型上验证通过。未知机型请先用 --dry-run / --simulate，并参考 README 的探测方法确认寄存器。

安装包会触发 SmartScreen 吗？

当前发布包尚未代码签名，首次运行可能出现提示。我们正在申请 SignPath Foundation 的免费开源签名；在此之前，可以用 SHA256SUMS.txt 校验文件完整性。
