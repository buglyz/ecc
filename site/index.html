Capabilities

全方位硬件管控，兼顾极致静音与高能散热

从底层内核驱动通信，到应用层闭环控制算法，打造安全可靠的温控系统。

微软 WHCP 签名内核驱动

默认集成 PawnIO 2.x 官方驱动（LpcACPIEC.bin），通过微软官方 WHCP 认证并完美兼容 Windows 核心隔离/内存完整性（HVCI），告别传统 WinRing0 等驱动造成的安全拦截风险。

自适应目标温度模式

独创闭环比例控制律（KP + 动态死区 + 升降速率门限），设定如 66°C，控制器自动根据温差微调风扇上限，“放开快、收紧慢”，彻底消除风扇频繁拉高降下的恼人啸叫。

双向防交叉阶梯曲线

5 控制点线性插值，支持 Canvas 画布拖拽圆点与调音台式输入框毫秒级双向同步。内置前后节点单调递增约束算法，杜绝温度节点交叉引起的逻辑错乱。

双擎并排对称中控台

全新重塑的并排双引擎 WebUI：左侧风扇调控核心中枢，右侧全景历史时序监控（1–480 分钟自适应抽样，零掉帧无卡顿），集成手动转速快速接管条。

独立硬件看门狗进程

分离的独立守护进程监控主控心跳；若主程序发生崩溃、死锁或被强杀，看门狗在 30 秒心跳超时后自动将 EC 上限重置为 0xFF，无缝退还给主板固件，彻底杜绝过热隐患。

原厂控制权仲裁与高温保护

感知原厂 ControlCenter 的 FanControlStatus，原厂激活时主动让渡。CPU≥92°C 或 GPU≥87°C 自动触发两阶段高温硬保护，交还主板全速排热。

Architecture

底层闭环工作原理与硬件交互架构

每秒采样传感器温度，经由降噪平滑、策略合成与控制门控，安全写入 EC 嵌入式控制器。

1. 温度采集 (Sensors)

通过独立常驻进程桥接 LibreHardwareMonitor 与 GmwmiCli 只读读取 CPU 与 GPU 核心温度，具备指数退避防反复崩溃机制。

→
2. 策略合成与平滑

加权（0.7·CPU + 0.3·GPU）、取最大值或单路通道合成代表温度。周期内 6 次采样取算术均值，过滤瞬态脉冲噪声。

→
3. 调控算法计算

曲线模式：5 控制点分段插值。
目标模式：偏离误差 × KP 自适应计算，受限于 Min/Max 范围与升降步长限制。

→
4. 门控安全决策

1.5°C 迟滞滤波过滤微小温差抖动；10 秒心跳机制防止固件收回控制权；高温硬保护阈值优先裁决。

→
5. PawnIO EC 写入

通过 WHCP 签名的 PawnIO 设备直接读写 EC 寄存器 0x2C/0x2D，并立即回读 0x2E/0x2F 与 RPM 实际占空比验证。

EC 核心寄存器分布映射 (蓝天/神舟模具)

寄存器地址 物理功能 读写属性 数值规范与工程意义
0x2C / 0x2D CPU / GPU 风扇占空比上限 可读可写 写入 0x00–0x64 (0–100%) 为上限；写入 0xFF 立即交还主板 EC 原厂曲线接管
0x2E / 0x2F EC 实际调控占空比 只读 主板硬件实际执行的 PWM 占空比（EC 通常以约 10 秒时间常数的阻尼平滑逼近设定的上限值）
0x58 / 0x59 CPU / 拓展硬件传感器温度 只读 当前 EC 读取到的摄氏度整数，用于高温保护比对与回退传感器核验
0xB0 / 0xB1 Fan 1 实际物理转速 (RPM) 只读 小端 16 位无符号整数（低字节在 0xB0，高字节在 0xB1），反映真实转速
0xB2 / 0xB3 Fan 2 实际物理转速 (RPM) 只读 小端 16 位无符号整数（低字节在 0xB2，高字节在 0xB3），反映真实转速
Comparison

三大风扇调控模式深度对比

根据日常办公、影音娱乐或重度游戏负载，自由选择最契合当前工况的控制策略。

阶梯曲线模式

Curve Interpolation

基于 5 个自定义控制点的分段线性插值查表算法，直观可控，符合直觉。

  • 调控依据：综合计算得到的代表温度。
  • 平滑机制：1.5°C 迟滞滤波，消除临界点震荡。
  • 交互特性：支持 Canvas 拖动圆点与表格数值实时双向联动。
  • 适用场景：想要精准掌控某个特定温度区间的转速分界线。

自适应目标温度模式

Target Feedback (闭环推荐)

比例控制律 + 死区滤波 + 升降速率限制，算法自动调整转速上限将温度维持在目标值。

  • 控制律：desired = Bias + KP × (avg - Target)。
  • 温度输入：固定采用 CPU 与 GPU 较高的一路，避免平均抵消热源。
  • 速率门限：默认 UpStep=+30%（放开极速）、DownStep=-10%（收紧极稳）。
  • 适用场景：游戏与高性能创作，追求安静与性能的动态最佳平衡点。

手动固定转速模式

Manual Speed Override

直接锁定固定的风扇占空比上限，完全绕过任何温度曲线与算法计算。

  • 执行权重：在常规模式中具有最高优先级，一键锁定。
  • 快速接管：直接在遥测驾驶舱提供开关与 0–100% 滑块。
  • 安全兜底：当触发 CPU≥92°C 或 GPU≥87°C 高温保护时，仍将强制全速。
  • 适用场景：高负载前提前暴力强冷降温，或低负载下追求绝对恒定声音。
Quick Start

最省心

包含静默安装 PawnIO 驱动逻辑与自动计划任务部署，支持覆盖更新与标准控制面板卸载。

  1. 从 Releases 下载最新 ECC-Setup-v2.0.0.exe。
  2. 双击运行安装向导（自动请求管理员提权，默认安装至 %ProgramFiles%\ECC）。

方式二：便携版 ZIP (免安装)

纯绿色

FAQ

常见问题解答 (FAQ)

关于安全性、驱动认证、硬件兼容性与配置持久化的解答。

需要关闭 Windows 11 的“内存完整性 / 核心隔离”吗？

完全不需要！在 2.0.0 版本中，默认的 EC 读写后端已经全面升级为 PawnIO 2.x。PawnIO 驱动拥有微软官方 WHCP 签名，100% 兼容 Windows 11 HVCI 内存完整性机制。你可以在完全开启核心隔离的情况下正常稳定运行，绝无任何驱动拦截报错。

开机自启动为什么有时候不会弹出 UAC 管理员提权窗口？

这是 ECC 的安全机制设计：如果通过官方安装包安装在 C:\Program Files\ECC 下，由于该目录属于受保护的系统安全路径，开机自启会使用系统计划任务的 HIGHEST 特权级静默启动，免去每次开机点击 UAC 提权；如果安装在非保护目录，开机自启则使用普通用户级任务，登录时程序会请求一次 UAC 确认，杜绝以高权限自启非保护目录的提权安全风险。

如果软件崩溃或卡死，笔记本风扇会停转导致硬件过热吗？

绝对不会。ECC 设计了多重冗余安全机制：

  • 独立看门狗进程：主程序启动时会同步拉起一个独立的看门狗进程监控心跳；若主程序崩溃、被任务管理器杀死或线程死锁导致 30 秒无心跳，看门狗会立即向 EC 写入 0xFF 释放所有控制权，交还给主板 BIOS 原厂风扇曲线。
  • 传感器失联保护：若温度传感器连续 3 个周期未读取到有效数值，控制器主动退出并写入 0xFF 释放硬件。
  • 两阶段高温硬保护：只要侦测到 CPU≥92°C 或 GPU≥87°C，无视任何软件锁定，强制把控制权归还给主板全力排热。
目标温度模式下为什么风扇转速有时候降不下来？

在蓝天/神舟等大多数笔记本架构中，EC 寄存器 0x2C/0x2D 的物理意义是风扇占空比上限（Speed Cap）。这意味着：ECC 可以将风扇转速压制到原厂曲线以下以换取静音，但如果主板固件自身的温控规则在当前温度下要求更激进的高转速，由于硬件是“取二者较严格者”，软件上限不会越权强行停转风扇。此外，若当前处于 UpStep/DownStep 降速速率限制中，风扇也会以设定步进缓慢收紧，避免瞬间忽快忽慢。

我的笔记本能用吗？如何排查兼容性？

本项目已在神舟 Hasee QNLXS（i7-12650H + RTX 4060，BIOS SQ131）完成 100% 验证，并适配大多数蓝天（Clevo）及同方公模架构的机型。不同品牌和主板 EC 寄存器定义可能不同。建议未知机型首次运行添加 --simulate 或 --dry-run 启动，并在管理员终端中核验读写响应后再实际接管。

软件会收集我的电脑温度或上传数据到云端吗？

完全不会。本软件为 100% 纯本地离线开源项目，不包含任何云端通信接口、数据收集、遥测探针（Telemetry）或用户账号体系。Web 控制台仅绑定回环地址 127.0.0.1，并具备页面 Session Token 与 Host 白名单防跨域拦截防护，网络绝对安全。
